# Contributing Guide

> Wird in einer späteren Phase vollständig definiert.

## Development Workflow

1. Branch erstellen
2. Changes implementieren
3. Tests schreiben (wenn vorhanden)
4. Commit mit aussagekräftiger Message
5. Pull Request erstellen

## Code Style

- TypeScript Strict Mode
- ESLint Rules befolgen
- Prettier für Formatierung
- Functional Programming bevorzugt
- Domain-orientierte Struktur

## Commit Messages

Folge Conventional Commits:

```
feat: Add new feature
fix: Fix bug
docs: Update documentation
style: Format code
refactor: Refactor code
test: Add tests
chore: Update dependencies
```

## Pull Requests

- Beschreibung der Changes
- Screenshots bei UI-Changes
- Tests durchführen
- Linting ohne Fehler

## Testing

> Testing-Guidelines werden in Phase 2 definiert.
